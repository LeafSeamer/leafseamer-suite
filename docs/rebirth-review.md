## 1. 审阅结论

### 1.1 已解决的方案冲突

| 编号 | 冲突或遗漏 | 当前稿处理 |
| --- | --- | --- |
| R01 | 曾建议单仓库，用户要求独立仓库 | Organization＋四组件＋Suite；不强制 Submodule |
| R02 | 曾建议继续使用 PostgreSQL | 新版运行库改 SQLite；旧运行现状仍为 PostgreSQL |
| R03 | 保留功能与不迁移旧数据容易混淆 | 保留能力，空库启动；不开发旧数据迁移工具，仅建议文档 |
| R04 | GUI 脱离 NodeCG 与保留图文可能冲突 | GUI 重做，图文通过可选外部 NodeCG 桥接 |
| R05 | 独立 Controller 与统一登录可能耦合 | 独立本地账户，套件显式签发方及配对；具体宿主列入待办 |
| R06 | “手动优先”可能只是请求插队 | 持续接管、派发前校验、明确释放、不补发；在途不可取消限制显式记录 |
| R07 | NTP 时间戳可能被误当精确同步保证 | 时间质量可观测，绝对排期门控；不承诺帧同步 |
| R08 | 工作进程和 iframe 可能被误当安全沙箱 | 明确隔离目标，第三方授权及安全设计单列 |
| R09 | 运行库去 PostgreSQL 会误删排期数据源 | 保留外部 PostgreSQL 只读排期导入能力 |
| R10 | 状态机运行中修改与副作用语义未明确 | 定义版本激活仍待确认；状态提交、重试恢复及并行失败产品方向已由 Q37—Q44 确认，接口与验证待落实 |
| R11 | 排期展示页可能被遗漏 | 排期服务归 Seamer，播出展示经 NodeCG 兼容 |
| R12 | 许可切换可能覆盖原有声明 | 新版主许可与历史／第三方义务分开，不修改旧提交许可 |

### 1.2 审阅通过的边界

- Controller 拥有设备连接与控制；Seamer 拥有自动化，手动和自动动作走同一执行入口。
- API／SDK 与 GUI 解耦；无专用面板也能使用模块能力；SDK 不承担中心服务职责。
- 一个 Seamer、多 Controller、单设备归属，与按服务隔离 SQLite 的方案一致。
- 旧数据免迁移不影响新版自身备份、恢复及后续 Schema 升级。
- 无断网自治不免除连接状态、时间未同步、重启未知结果和同步快照完整性处理。
- 旧 README 保留 NodeCG／PostgreSQL 的历史使用说明，并按新授权增加停止维护及后继项目入口；不得改写成新版已可部署。

Q35—Q44 已确认：整台设备接管、版本门控、在途分类、完成证据、必需动作成功后提交目标状态，以及受限重试、显式恢复、单持有人转交和并行失败收敛。T04—T06 的产品方向已补齐，相应接口、竞态及持久化验收仍未完成。细粒度接管见设计稿 13.1 路线图。Q45—Q49 继续讨论预检布防、运行配置激活、接管持久化恢复、触发事件时效及反馈循环，仍属待确认建议。

T07 需区分系统 NTP 对接与应用层校时。未经测量不写固定精度承诺；未同步时绝对排期阻止，手动与相对计时仍可用。不得把每个 API 请求都变成一次阻塞 NTP 查询。

T08/T13 需区分单服务快照和套件一致性。备份文件、密钥和版本清单都恢复成功之前，不能声称可恢复。命令副作用与 SQLite 提交无法组成设备级原子事务。

以下均为未来验收要求，本轮未运行。每项应有命令／环境、预期、实际结果和证据位置。

| 领域 | 核心验收场景 |

| SDK／API | 独立客户端接入；能力注册与更新；版本不兼容、无效参数和越权被拒绝 |

| NodeCG | 明确 bundle 的动作／状态往返；输出页及原操作台；外部操作限制可见 |
