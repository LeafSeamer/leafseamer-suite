# 资源失效后的持久关闭通知候选

状态：待审阅。与[132表结果依赖](RESULT_DEPENDENCY.md)组成137表，不改旧候选。这里只规定并核验持久投递和恢复引用，未实现真实worker或产品迁移。

已知事实：现有`CLOSE_GATE`支持在数据库失败时进行只关不换持有人的保护；其ACK只证明指定出口关闭，不提供逐许可核销。资源失效已能在本机锁存，但原表没有完整投递与恢复关闭引用。（来源：[F02/F03](../../rebirth-f02-f03-design.md)、[资源存储](resource.sql)、[当前设备IPC](../df03-service/ipc.schema.json)。）

基于这些事实，推荐继续使用CLOSE_GATE，不伪造RUN或接管授权。持久路径与数据库不可写时的紧急路径并存；后者不能伪造持久incident或ACK，恢复时仍须完整取证。

## 记录与事务

| 对象 | 字段与含义 |
| --- | --- |
| ro_incident | release_id指向首次释放失效、device_id及共享issued_revision切点；与失效双向外键并同事务自动写入 |
| ro_target | incident与exit_id的唯一目标、固定intent_id；覆盖当时全部未获监督退役证明的出口，包括旧连接；保护期间新出口同注册事务补入 |
| ro_attempt | 唯一attempt_id、close_id、目标及连续ordinal、不可变逻辑message_body、验证与审计正文；提交后才能进入发送队列 |
| ro_ack | 原attempt、可信资源validation、ACK摘要与正文；验证须绑定close_id、父命令、设备及resource-close/1政策 |
| ro_recovery_target | 恢复时完整目标集及每项采用的ACK或监督退役证据；与恢复提交同事务，之后不可变；每份ACK只能被一次已提交恢复采用 |

首次失效触发incident与完整活出口通知写入。任何通知插入失败会回滚整个失效事务；真实writer随后必须进入数据库故障保护路径，不能因事务失败继续许可。未注册出口由受监督域约束禁止发送；注册期间若设备已保护，必须先登记新关闭目标且出口初始关闭，不能先开闸。

目标集合是追加的历史事实，不因某项已ACK而删除。已证明退役的出口不需要网络关闭，但其许可未知状态与资源仍由原核销证明负责。这里的共享水位用于审计，不声称CLOSE_GATE已完成逐传输屏障；完整FENCE/AUTH/TIME/RUN覆盖继续独立处理。SQL生成的随机身份必须持久后才使用，冲突时事务失败，不拼接可能歧义的外部ID。

## 投递、迟到与恢复

同一attempt重投必须使用同一个close_id和原逻辑正文；协议信封序号可以变化，不能把它当设备动作重传。worker按当前完整会话和close_id保存不可变接收正文及原回执；重复只返回原回执，不再次改变闸状态，即使随后已有合法OPEN_GATE。相同身份正文不一致属于协议故障。缓存丢失或会话改变不能用“未见请求”证明未关闭或未发送，应进入现有重新取证/监督退役流程。

必要的新关闭尝试使用新close_id并递增ordinal。最新尝试存在时，旧ACK仍保存，但不能代替最新尝试的关闭资格。发送协调器必须在同一有序出口串行化“最终选择最新attempt并写IPC”和“采用ACK并允许OPEN_GATE”：新尝试建立后旧未提交消息不得再进入队列；只有最新已发送尝试的有效ACK或精确监督退役证据才能解除该出口的关闭待办。当前SQL不实现这个I/O线性化点，后续最终出口实现与故障验收必须验证，不能只凭pending视图声明设备安全。

ACK提供者核验鉴权会话、方向、reply_to、完整设备集合、固定close_id与原正文；不能只比较客户端声明字段。ACK政策只证明关闭，不授予资源clear或接管ready。恢复仍要求全部历史失效、全部资源已安全，以及完整目标集的当前有效关闭证明。空目标仅在注册表确实为空或全部已证明退役时成立，不能截断清单。

关闭ACK或恢复证明撤回时，本机保护重新可见，并补上此时存在的新出口目标。旧恢复只引用原ACK，不会因后来收到新ACK而自行恢复；必须提交新的完整恢复记录。已经恢复后不得继续发送旧通知；迟到旧响应保留历史，不能覆盖当前证据。

恢复可能允许出口重新开闸，所以已被任何已提交恢复采用的ACK不能再次充当新恢复的关闭证据。设备再次进入保护时，对该设备全部历史incident补齐当前活出口，并将已消费ACK的目标重新列入待关闭集合；新尝试必须采用新的close_id。同设备的新失效也遵守此规则，不能只关闭新incident的目标而遗漏旧事件与后来注册的出口。历史恢复仍引用原ACK判定自身证据，不因“已消费”立即自我失效；最新尝试或原证明撤回则使它失去当前恢复资格。监督退役事实不受一次ACK消费限制，已退役出口无须重新关闭。

## 容量、故障与验收

关闭通知不受普通设备动作预算扣费；需要独立保留的存储和发送容量。内部目标集不以单帧256上限截断，每个出口单独关闭，队列满或库不可写触发原紧急CLOSE_GATE路径。具体容量profile、最终发送提供者及统一SDK/IPC字段映射仍待归并，不能将本候选当作已通过直播负载验证。

`build_protection_outbox.py --check`核生成字节；`check_protection_outbox.py --report`仅运行内存SQLite。报告[protection-outbox-report.json](protection-outbox-report.json)绑定输入；`--check-report --staged`不重跑测试。

73项验收覆盖失效与通知原子性、插入失败回滚、新旧出口、旧ACK晚到、ACK不清资源、恢复缺写/逐写回滚、恢复后禁旧通知、ACK或恢复证明撤回后重新关闭、历史ACK不得重复恢复、多事件完整覆盖、退役替代关闭。审阅新增反例先复现“恢复证明撤回但待关闭集合为空”的错误，再通过一次消费及设备级目标捕获修正。BODY/会话真实性是合成前提；真实IPC、缓存去重、最终发送并发、数据库故障紧急路径、磁盘和设备未运行。
