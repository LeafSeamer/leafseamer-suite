# LeafSeamer Rebirth 路线图

当前处于阶段 0，业务代码尚未开始。用户确认的产品方向与技术验收是两类独立门槛。

| 阶段 | 退出条件 |
| --- | --- |
| 0：设计及准备 | 收敛执行和恢复语义，完成 SDK/API 契约、旧能力矩阵、历史来源与许可边界；明确获准开始业务实现。 |
| 1：最小完整链路 | SDK、一个设备模块、Controller、GUI 手动控制、Seamer 自动化、SQLite 与时间质量贯通；接管、失败和重启场景验证。 |
| 2：功能覆盖 | 完成设计稿 18 个旧 bundle 的功能归属，包括设备型号、排期数据源、NodeCG 桥接、身份与备份。 |
| 3：套件验收 | Windows/Linux、原生与容器部署、版本组合、恢复演练及实际设备测试；发布产物和许可审阅完成。 |

## Q35：接管粒度

- 首期按整台设备实例接管，SDK 保留冲突资源声明，未知冲突按整台设备处理。
- 后续按模块开放通道、总线和输出粒度，必须描述资源重叠和宏的多资源占用。
- 开放前验证交叉冲突、转交与在途竞态；版本升级不得自动缩小已有接管范围。

## 历史与许可

旧仓完整历史保留在 Legacy。新仓目前只有文档与许可证，未导入旧业务代码。后续提取相关代码时登记旧路径、旧提交、新提交及来源许可；不把复制文件当成保留了提交历史，也不改写旧版本许可。

每项验收分别记录静态检查、模拟、浏览器、部署和真机证据。最小闭环完成不等于全部重构完成。
