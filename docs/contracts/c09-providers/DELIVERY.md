# 完整面板结果与局部释放边界

[delivery.py](delivery.py)将完整读集接到固定panel4的host.result信封，再进入同一Coordinator保护的有界队列。它使用 [typed_validators.py](typed_validators.py)的固定模型与方法结果引用，不更改公开契约，不调用订阅通道的旧选择。approved=false、runtime_ready=false；本包是可执行设计参考，尚不是完整面板宿主或生产输出Gate。

## 当前原件与唯一输出所有者

可信宿主在同一Coordinator内建立Delivery，提供当前公共通道绑定、完整激活引用、会话上下文、完整会话依赖集合和唯一出口。会话上下文精确包含selection、authority、public_binding_digest、activation_digest、installation_digest、approval_digest、authorization_digest及scope；完整引用必须经过当前模型验证且摘要相同。

next_sequence来自可信宿主已完成握手／激活后的实际方向序号。这里没有默认从1开始；同一Coordinator中，同一完整PublicBinding只能登记一次输出所有者，即使关闭也不复用。宿主必须保证该所有者独占对应方向，不能让Bundle、Projection或其他发送器绕过它分配序号。本包目前只实现host.result的available分支，其余帧、保护队列、传输ACK、ProjectionAck及接收顺序仍须统一归并，不能独立启动多个写入器来补足。

每个协调器最多登记64个输出通道，关闭墓碑保留到该协调器结束。每通道最多16个排队结果、262144规范字节，允许下调；每份完整请求与完整结果帧均不能超过65536规范字节。传入请求必须已经通过上游原始线字节限制，本入口只接收解析后的对象。64KiB限额包含绑定和信封，不只计算结果value；超限关闭通道，不裁剪结果或截断数组。

## 从读集到不可变帧

enqueue接收托管读集、封装候选、当前完整上下文、可信账本中的原始panel.request以及accepted_guard。原始请求须通过完整当前Schema，方法、request_id、输入规范摘要、公共绑定和激活引用必须相同。accepted_guard须重新核验该完整原请求确已受理／读取成功并明确返回True；结果结构本身不能证明领域操作已受理，更不能证明设备已完成。人工确认方法仍由已有确认和领域流程产生受理原件，不能因输出帧是accepted跳过确认。

完整帧固定type=host.result、status=accepted、reason_code=ok、projection_state=available，使用当前方法唯一结果SchemaRef。读集中的全部来源依赖会延续到排队结果；同时要求读集包含本通道的所有会话依赖，禁止只登记来源而漏掉导航或授权。帧构造、Schema及受理守卫在协调锁外执行，pending_deps使此期间的撤销仍能立即关闭输出；构造返回后重新核验依赖、队列容量、请求身份和读集期限。

最后在协调锁内消费原候选并登记不可变规范字节，两步之间没有解锁或外部回调。任何异常关闭通道并清空队列；已经受理的业务不会回滚、取消或重新投递。原业务查询仍由账本承担；尚未接入available以外结果分支时不能把输出失败解释为业务未受理。

每通道最多保留256个原请求ID及其完整请求摘要。同ID换方法、输入、目标或激活内容拒绝；查询同一原请求可以用新的当前读集再次形成投影，取得新的输出序号，不重复执行业务。旧封装候选不能再消费。该登记只保护输出关联，不能替代持久幂等账本。

## 释放、撤权及失败结果

release只允许队首，一次最多一个释放在途。current_reader以队首完整字节摘要重新读取当前资格，返回完整当前上下文；该接口由可信宿主完成真实读权和来源核验，不能按摘要回显旧缓存冒充当前权威。慢重读在锁外执行，撤权不用等待它。

重读返回后，在同一协调锁内复核队首、完整依赖、上下文、单调时间和原读集截止，再调用一次可信非阻塞出口。读集消费不刷新截止；排队等待、阻塞和重试都使用原截止。观测到时钟倒退、异常、到期等号、来源或会话依赖撤销都关闭整个输出通道并丢弃尚未交付的队列，不尝试跳过一项后继续声称序号连续。

| 单次出口结果 | 返回状态与处理 |
| --- | --- |
| 明确接受完整规范字节 | handed_off，移除队首并推进sent_sequence |
| BlockingIOError且明确零字节 | would_block，保留队首且不推进；下一次必须再次重读当前资格 |
| 返回部分字节，包括返回0 | partial_closed，关闭并清空队列，不补发后缀 |
| 异常、可能部分写入、布尔或越界返回 | indeterminate，关闭并清空队列，不猜测成功 |

交付先取得协调锁时，允许这一次交付完成，然后撤权关闭后续输出；撤权先取得锁时，队列不再进入出口。完整接受只证明交给指定出口，不证明面板收到、展示、ACK、持久化或设备效果。sent_sequence保留已交付历史，关闭不把它改成未发生；进程退出不恢复内存队列或自动重发。

可信出口不得重入协调器、阻塞等待可写、缓存到未受门保护的异步队列或自行重试。SocketSink实际调用一次非阻塞明文socket.send，仅用于本机传输验证；生产浏览器MessagePort、HTTP、WS、TLS的内部缓存、克隆、分帧和关闭边界须分别接线验证。本地关门只阻止此入口后续调用，不证明已排入操作系统、浏览器或远端队列的字节已经撤回，也不替代底层连接的物理关闭。
